# Декомпозиция: данные, задача, принятые решения, точки роста Recall@50

Состояние на 2026-09-16: лучшее решение H1 + H2 + H4 (переранжирование) — **0.8796 на бенчмарке**, 0.9225 на валидации,
использовано 3 попытки из 7. Все числа посчитаны на данных проекта; журнал экспериментов — `docs/hypotheses.md`.

## 1. Задача

- Кандидатогенерация для поиска услуг Авито: на запрос вернуть ≤50 `item_id` из корпуса в 189 212 объявлений.
- Метрика: Recall@50, усреднение по запросам; порядок внутри 50 не важен → всегда заполнять все 50 мест.
- «Правильное» объявление = выбор пользователя (клик/контакт), обычно 1 на запрос (85 % сессий трейна).
- Ограничения: локальная воспроизводимость, без внешних API, подробные комментарии, open-source перечислить.

## 2. Данные — что важно для метрики

| Факт | Число | Следствие |
|---|---|---|
| Тексты бенчмарка встречались в трейне | 37 % | 63 % запросов — новые, история не спасает |
| Объявления трейна в корпусе | 5 % | запоминать item_id бесполезно, учиться на текстах/категориях |
| Выбор в городе поиска (городской уровень) | 93 % | гео — сильнейший фильтр/признак |
| Поиск по региону/стране | бенч 17 %, трейн 11 % | нужен гео-пул регион → города |
| Фильтр «Вид услуги» совпадает с выбором | 98 % | почти жёсткий ярус |
| Запросы без фильтров | бенч 66 % | категорию надо предсказывать по тексту |
| search_category = 0 | бенч 9 %, трейн ~0 | не валидируется локально |
| Лексическое пересечение (стемминг, все поля) | 97.5 % пар имеют общее слово | BM25 силён |
| Шаблонные копии объявлений | 120 тыс. уникальных заголовков на 189 тыс. | внутри копий текст не различает |
| **Плотность тематических конкурентов** (объявления топ-3 предсказанных подкатегорий в городе запроса) | бенч медиана 78 (4.2 % пула), вал 62 (2.9 %) | **корпус «сгущён» вокруг тем бенчмарка → валидация легче** |

## 3. Принятые решения и их вклад

| Шаг | Что | Вал | Бенч | Перенос |
|---|---|---|---|---|
| H0 | BM25 (стемминг Snowball, заголовок+параметры+описание) в городе/регионе ∩ «Вид» | 0.829 | — | — |
| H1 | + e5-small: 40 мест BM25 + 10 энкодер | 0.8665 | 0.8356 | — |
| H2 | + гео-иерархия: соседи 100 км (вес 0.6), регион: ядро 90 % выборов, хвост 0.8 | 0.8920 | 0.8514 | ~60 % |
| H3 | «Тип» + предсказанная подкатегория как веса | 0.8957 | не отправлялось | в H4 как признаки |
| H4 | переранжирование HistGradientBoosting, 36 признаков, кандидаты топ-300 BM25 ∪ топ-300 e5 | 0.9225 | **0.8796** | ~92 % |

Отклонено: rubert-tiny2 (шум), топонимы как буст (0), жёсткие фильтры по категории, lightgbm (системная libomp).

## 4. Где теряется recall сейчас (H4, валидация на объединённом корпусе: 0.914)

**Всего потеря 0.086 = 0.037 вне кандидатов + 0.049 в кандидатах, но ранг модели > 50.**

По сегментам (потеря вне кандидатов / ранг > 50):
- новый текст (freq 0, 63 % запросов): 0.026 / 0.031 — **две трети всех потерь**;
- город 0.026 / 0.034; регион 0.011 / 0.015 (при 17 % запросов — непропорционально много);
- пул > 10 тыс. (Москва, СПб): 0.009 / 0.018 — самый трудный ранжированный сегмент;
- без фильтра «Вид»: 0.027 / 0.033.

**Промахи в кандидатах (ранг > 50):**
- 58 % стоят на местах 51–100 → близко к границе, выигрываются лучшими признаками;
- медианы у промахов против попаданий: BM25 7.6 против 13.9, BM25 заголовка 2.4 против 7.4, ранг BM25 124 против 2;
- 14 % без общих слов с запросом (BM25 = 0), 29 % — подкатегория не в топ-5 предсказания,
  14 % — другой город при городском запросе, 12 % — выше стоит «тёзка» с тем же заголовком (почти неустранимо).

**Промахи вне кандидатов (192 объявления, 0.035):**
- 40 % вне гео-пула, 18 % в пуле с понижающим весом, 32 % без общих слов (BM25 = 0);
- лучший ранг: 30 % на 300–500, 31 % на 500–1000, 39 % дальше 1000.

**Глубина кандидатов (потолок, объединение списков по K из каждого):**

| K | BM25 ∪ e5-small | BM25 ∪ e5-base | BM25 ∪ small ∪ base |
|---|---|---|---|
| 300 (сейчас) | 0.9647 | 0.9653 | 0.9676 |
| 500 | 0.9745 | 0.9755 | 0.9772 |
| 1000 | 0.9858 | 0.9851 | 0.9878 |

→ e5-base не лучше e5-small (+0.0006), третий список +0.003. Увеличение глубины до 500 — +0.010 потолка.

**Что двигает модель (перестановка признаков, падение recall):** текст −0.643; гео −0.032 (из них `dist_km` −0.029);
категория −0.030 (`microcat_prob` −0.013); `rank_dense` −0.011, `rank_bm25` −0.006; объявление −0.006; запрос −0.002.
**У региональных запросов `dist_km` = NaN** — сильнейший гео-признак для них не работает.

**Обучение модели:** 5 тыс. запросов 0.9086 → 10 тыс. 0.9126 → 20 тыс. 0.9140 (насыщение, ~+0.001 за удвоение).
Гиперпараметры (127 листьев, lr 0.03) — без изменений; 300 негативов вместо 100 — хуже (0.9118);
только жёсткие негативы — поломка (0.175), модель не видит «лёгкий» фон.

## 5. Точки роста (приоритет = ожидаемый прирост на бенчмарке / стоимость)

### A. Ранжирование (потеря 0.049)
1. **Коллаборативный признак через похожие запросы трейна** — для нового текста найти k ближайших fit-запросов
   (e5-small), взять эмбеддинги выбранных ими объявлений (включая объявления только из трейна) и подкатегории;
   признаки: max/mean косинус кандидата к ним, доля подкатегории кандидата среди них. Бьёт в freq 0 (2/3 потерь).
   Нужны эмбеддинги ~327 тыс. объявлений только из трейна (~20 мин e5-small). Ожидание +0.005–0.015.
2. **Гео-признаки для регионов**: расстояние до ближайшего «ядрового» города региона и доля выборов этого города,
   расстояние между городом объявления и городом запроса (для соседей). `dist_km` — второй по силе признак, а для
   17 % запросов бенчмарка он пуст. Ожидание +0.002–0.006.
3. **Точные текстовые признаки**: доля стеммов запроса в заголовке / прайс-листе / параметрах, все слова в заголовке,
   биграмма запроса в тексте, совпадение «Тип автосервиса» / «Предмет», косинус запроса к заголовку отдельно.
   Направлено на медианный промах (слабый BM25 заголовка). Ожидание +0.003–0.006.
4. **Улучшенный предсказатель подкатегории**: смешать стеммы и kNN по похожим запросам (п. 1). Ожидание +0.002–0.004.
5. Дёшево: 40 тыс. обучающих запросов, ансамбль 3–5 сидов, смешанные негативы (случайные + часть жёстких).
   Ожидание +0.001–0.003.

### B. Кандидаты (потеря 0.037)
6. **Глубина 300 → 500** в обоих списках: потолок +0.010, строк ×1.6. Ожидание +0.003–0.006.
7. **Гео-добор вне пула**: для городских запросов — отдельный неглубокий список BM25 по всему корпусу с признаком
   «удалённо/онлайн» (40 % внекандидатных промахов вне пула). Ожидание +0.001–0.003.
8. **Дообучение e5-small на парах трейна** (запрос → выбранное объявление, in-batch негативы + негативы из того же
   города): бьёт в BM25 = 0 (32 % внекандидатных, 14 % ранжированных промахов) и в семантику новых текстов.
   Самый крупный потенциал (+0.01–0.02), но на M1 — часы; лучше GPU-машина.
9. e5-base / USER-base: e5-base по данным не даёт прироста — не приоритет; USER-base досчитается и будет проверен той же
   кривой глубины (одна команда).

### C. Разрыв валидация → бенчмарк (−0.043)
10. **«Трудная» валидация**: добавить в корпус валидации тематических конкурентов (объявления только из трейна тех же
    подкатегорий в тех же городах), чтобы плотность совпала с бенчмарком (4.2 % против 2.9 %). Даёт более честную
    локальную цифру и, главное, обучающие признаки для переранжирования в условиях, как на бенчмарке.
    Не даёт прирост напрямую, но снижает риск выбрать «оптимистичную» гипотезу.
11. Категория 0 (9 % бенчмарка) — непроверяема; следить только, чтобы признаки `is_services`/`has_vid` не ломали их
    (у них нет фильтров, поведение как у обычных запросов без фильтра).

### D. Практически неустранимое
- «Тёзки» (одинаковые заголовки выше правильного) — ~12 % ранжированных промахов.
- Правильные объявления глубже 1000 и вне гео — ~40 % внекандидатных промахов.
